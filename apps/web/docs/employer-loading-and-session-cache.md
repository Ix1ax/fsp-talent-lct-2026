# Загрузка кабинета работодателя

После авторизации `useEmployerResources` запускает компании и справочники
условий независимыми эффектами в одном commit. Потребности начинают загружаться
после компаний, независимо от справочников. Только ошибка авторизации или
компаний блокирует открытие кабинета; пустой список компаний открывает создание
компании.

У справочников условий отдельные загрузка, ошибка и повтор. Повтор не затрагивает
компании и потребности и не сбрасывает ввод редактора. Пока справочники недоступны,
просмотр использует сохранённые значения и подписи с ID, а выбор специализации,
грейда и форматов временно недоступен. Название, описание и остальные поля можно
редактировать.

Полный каталог навыков в bootstrap больше не загружается. Редактор запрашивает
до 50 навыков на страницу, затем ищет по `q` с задержкой 300 мс. Старый поиск
отменяется, его поздний результат игнорируется. Уже найденные названия и
выбранные ID сохраняются независимо от текущей выдачи; выбранный навык можно
удалить даже вне результатов поиска. Публичный API не поддерживает чтение навыка
по ID, поэтому неизвестное название заменяется подписью `Навык <ID>`, пока навык
не встретится в выдаче. Ошибка поиска имеет собственный повтор и не скрывает
потребности.

Компания, вкладка, offset и потребность читаются из URL до запуска запросов
потребностей. Offset проверяется на целое значение 0–10 000. При изменении
компании текущая выборка сразу становится недействительной; старые запросы
списка и детали отменяются. Их поздние ответы не применяются. Запись справочников
не участвует в ключах редактора, поэтому их загрузка не перемонтирует форму.

# Серверная сессия

`loadSession` и `getMe` обёрнуты в `React.cache()`; хедер и
`requireSessionUser` используют одну и ту же функцию `loadSession`. Кеш React
живёт в пределах серверного рендеринга HTTP-запроса. Межпользовательский кеш,
`unstable_cache` и кеш токенов не добавлены. HTTP-запросы к API выполняются через
существующий Axios-клиент.

На локальном Next.js с synthetic API `/candidate/profile` измерено:

| Проверка                                          | Вызовы `/api/v1/me`                                |
| ------------------------------------------------- | -------------------------------------------------- |
| Хедер + защищённый layout до изменения            | 2                                                  |
| Тот же рендер после изменения                     | 1                                                  |
| Два последовательных HTTP-запроса после изменения | 2 суммарно                                         |
| Параллельные запросы кандидата и работодателя     | 2 суммарно, собственные маршруты                   |
| Ошибка 503 и следующий успешный запрос            | 2 суммарно, ошибка не переиспользуется             |
| Гостевой запрос после logout                      | 0 дополнительных вызовов, старого пользователя нет |

Повторяемые проверки:

- `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.
- `node scripts/review/server-session.mjs` — HTTP-проверки кеша и изоляции.
  `--baseline` проверяет прежнее число вызовов на версии без кеширования.
- `node scripts/review/employer-resources.mjs` — зависшие и недоступные ресурсы,
  независимый повтор, поиск, прямая ссылка, быстрая смена компании, пустое
  состояние, создание, сохранение, архивирование и восстановление.

Сценарии используют mock API на 5191, Next.js на 5185 и Chrome CDP на 9224.
Адреса задаются через `REVIEW_API_URL`, `REVIEW_APP_URL`, `REVIEW_CDP_URL`;
скрипты разрешают только loopback-хосты.
