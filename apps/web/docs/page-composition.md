# Композиция страниц

В `app/**/page.tsx` оставляем metadata, проверку доступа, серверную загрузку данных
и подключение экрана из `screens`. Разметка секций и состояния интерфейса находятся
в компонентах экрана. `loading.tsx` и `error.tsx` подключают соответствующие экраны.

## PageWrapper

`PageWrapper` из `shared/ui` владеет единственным `main` страницы. Внутри него
используем секции и блоки, без вложенного `main` и повторного контейнера страницы.

| Вариант               | Назначение           | Оформление                                                                                                     |
| --------------------- | -------------------- | -------------------------------------------------------------------------------------------------------------- |
| `page` (по умолчанию) | Обычные страницы     | До 1280 px, горизонтальные отступы 16/32 px, верхние 24/40 px, нижние 40/64 px, расстояние между блоками 32 px |
| `landing`             | Лендинг              | Секции самостоятельно задают ширину, отступы и фон                                                             |
| `login`               | Вход                 | Центрирование, общий горизонтальный контейнер, вертикальные отступы 48/96 px                                   |
| `workspace`           | Кабинет работодателя | Общие ширина и отступы, внутренняя композиция задаёт сетку и расстояния                                        |

Изменение горизонтальных отступов и ширины делается через существующие
`container-page`, `page-rhythm` и `--container-page`. `className` нужен для локального
поведения (например, scroll-margin), а не копирования контейнера. Нативные props,
ARIA-атрибуты и React 19 `ref` передаются на `main`.

Админка сохраняет свою оболочку `AdminShell`, ширину 1440 px и мобильную навигацию.
Состояния OIDC сохраняют отдельную композицию экрана авторизации.

## PageHeader

Заголовок собирается из частей. `Row` задаёт адаптивное расположение текста и
действий, `Content` группирует заголовок и описание. Следующие блоки внутри корня
могут содержать вкладки или дополнительный контекст.

```tsx
<PageWrapper>
  <PageHeader>
    <PageHeader.Row>
      <PageHeader.Content>
        <PageHeader.Title>Достижения ФСП</PageHeader.Title>
        <PageHeader.Description>
          Управляйте привязкой и импортированными результатами соревнований.
        </PageHeader.Description>
      </PageHeader.Content>
      <PageHeader.Actions>
        <Button asChild variant="outline">
          <Link href={STATIC_ROUTES.CANDIDATE}>В кабинет</Link>
        </Button>
      </PageHeader.Actions>
    </PageHeader.Row>
  </PageHeader>
  <CandidateAchievements />
</PageWrapper>
```

`Title` — единственный `h1` страницы. Каждая часть принимает нативные атрибуты и
`className`. Описание и действия с пустым содержимым не создают пустых контейнеров.
Для обычного текста фигурные скобки не нужны; выражения используем для данных.

## Границы компонентов

Выносим самостоятельные секции, формы, карточки и сложные состояния загрузки,
ошибки или отсутствия данных. Запросы, таймеры и состояние сценария остаются у
владельца экрана или в его model; дочерние блоки получают данные и обработчики.
Не создаём компонент для каждой строки разметки.

В кабинете работодателя скрытые формы профиля, документов, команды и вакансий
остаются смонтированными при переключении разделов, чтобы сохранять черновики.
Разделение на компоненты не должно заменять `hidden` условным размонтированием.

## Стиль компонентов

Компоненты используют блочное тело стрелочной функции с явным `return`, даже
если в них нет логики. Короткие обработчики и callbacks коллекций могут сохранять
неявный возврат. Правило для компонентов закреплено в ESLint.

```tsx
export const ExampleSection = () => {
  return <section>Содержимое секции</section>;
};
```

## Оформление обычных страниц

Страницы заданий и прохождения тестирования используют тот же `PageHeader`,
что и кабинет: заголовок 24/30 px, радиус `rounded-2xl`, отступы `p-5 sm:p-6`.
Навигация назад находится в `PageHeader.Actions`; на странице отдельного задания
навигация остаётся перед заголовком, который загружается вместе с данными.

Панели и формы используют `rounded-xl`, `bg-card`, отступы 20/24 px.
Для карточек вопросов, результатов и прогресса используем `Card` и его части.
Расстояние между блоками страницы задаёт `PageWrapper` (32 px), между связанными
панелями — `gap-6` (24 px). Скелетоны повторяют отступы готового содержимого.

Обычные действия используют стандартный размер `Button` (40 px) без локального
увеличения высоты. Переходы назад и вторичные действия — `outline`, главное
действие — `default`. Для многострочного текста допускается `h-auto min-h-10
whitespace-normal`. Строки выбора ответов сохраняют увеличенную область нажатия.

## Условные состояния

Вложенные тернарные выражения запрещены правилом ESLint `no-nested-ternary`.
Выбор подписи из нескольких вариантов выносим в именованную функцию с `if`
и ранними возвратами. Загрузку, ошибку, пустой результат и содержимое сложного
блока выносим в отдельный компонент. Порядок проверок сохраняет приоритет
исходного сценария: например, ошибка подборки показывается перед старыми данными.
Хуки загрузки и черновики остаются в исходном владельце состояния.

## Экран авторизации

`AuthLayout` сохраняет отдельную композицию: фирменный фон, логотип над карточкой,
переключатель темы и ссылка возврата. Его карточка использует `PageWrapper`
с вариантом `auth` и владеет единственным `main`. `LoginPage` подключает оболочку
и `LoginPanel`; содержимое входа находится в панели. Маршрутный layout возвращает
`children`, не добавляя шапку, подвал или дополнительный контейнер.
