# Операционная админка

Новые разделы используют отдельную административную сессию и `/api/v1/admin` через существующий API proxy. Контракты сверены с OpenAPI локального API от 10 октября 2026 года. Кабинеты работодателя и кандидата не изменяются.

- `/admin/overview`: текущая статистика, диаграммы распределения статусов, очереди компаний и навыков. Исторических данных API не предоставляет; временные графики не строятся. Легенды ведут в отфильтрованные списки.
- `/admin/companies`: поиск по названию/ИНН, независимые фильтры подтверждения (`status`) и доступа (`access_status`). Карточка содержит отдельные блоки проверки и доступа, причину/дату блокировки, участников, файлы и документы текущей заявки. Решения о подтверждении передают `expected_version`; блокировка/разблокировка отправляется в `/companies/{id}/status` без версии проверки, с обязательной причиной. Конфликт требует проверки актуальной карточки.
- `/admin/users`: поиск по имени, подтверждённой почте аккаунта, контактной почте кандидата, ID аккаунта и профиля; фильтры роли и статуса. Список и карточка показывают имеющиеся имя и почту. Карточка содержит источник имени, дату синхронизации аккаунта и связанные компании, включая неактивное участие. Блокировка/разблокировка требует причины. Удалённых пользователей восстановить нельзя; роль `admin` меняет только superadmin. `candidate_id` в связанных списках — ID профиля.
- `/admin/needs`: фильтры компании, специализации, грейда, статуса, текста; условия, навыки, форматы работы и модерация.
- `/admin/offers`: фильтры компании, профиля кандидата и статуса; сохранённые условия и даты взаимодействий. Изменения решения кандидата нет.
- `/admin/tasks`: задания компаний и фильтр **статуса модерации**. Предварительного одобрения публикации нет. Карточка показывает состояние приёма, срок, файл и число решений. Скрытие закрывает приём, снятие модерации не открывает его снова.
- `/admin/attempts`: фильтры профиля, специализации, грейда и статуса; метаданные, итоговый балл и порог. Чтение не завершает попытку.
- `/admin/audit`: единый журнал с источником, именем/почтой и ID автора, объектом, действием и включительным периодом. Данные автора отражают текущую запись аккаунта, а не снимок на момент события. Время выбора и отображения — Москва; запросы передают RFC3339.

У участников компании показываются имя, почта, ID, роль аккаунта, роль в компании и отдельные статусы членства и пользователя; причина личной блокировки также видна. В списке администраторов выводится выделяемый ID. Диалог решения показывает название/имя, доступную почту и ID выбранной записи.

Имена могут менять сами пользователи; они не удостоверяют личность. Подтверждённая почта аккаунта и самостоятельно указанная контактная почта кандидата обозначены отдельно. Эти поля читаются только из административных endpoint; публичные профили, банк кандидатов и интерфейс работодателя не расширяются. Блокировка адресуется стабильному ID аккаунта. Новые переменные окружения не нужны; требуется backend с административными полями идентификации и endpoint `/admin/users/{id}/companies`.

Причины решений ограничены 2000 символами, защищены от управляющих символов и сохраняются с защитой от повторного отправления и потери несохранённых данных. Документы и файлы заданий скачиваются с Bearer-заголовком через общий транспорт с таймаутом и обработкой истечения сессии. Токен не попадает в URL. Приватные решения кандидатов не доступны через эти разделы.

Блокировка компании закрывает рабочие действия для всех её участников и взаимодействия кандидатов с её заданиями и предложениями. Подтверждение, документы и история сохраняются; администратор продолжает видеть их. Личная блокировка работодателя применяется только к его аккаунту: блокировки пользователей и компаний независимы. Разблокировка требует причины и не снимает другие ограничения. Для заблокированной записи в списке и карточке показываются `blocked_reason` и `blocked_at`; после разблокировки плашка исчезает. Ссылки «История доступа» фильтруют журнал по объекту и событиям `company.status_changed` / `user.status_changed`.

На обзоре отдельная диаграмма «Доступ компаний» показывает `companies.active` / `companies.blocked` и ведёт к соответствующим спискам. Диаграмма подтверждения остаётся независимой. Рабочие изменения статусов недоступны при загрузке карточки или ошибке обновления.

Фильтры новых списков сохраняются в URL, проходят валидацию до запроса и передают только разрешённые непустые параметры. Пагинация использует `total`, по 20 записей, до offset=10000. Существующие административные разделы остаются доступны; `/admin` по-прежнему открывает справочники.

`Field`, `AdminSelect` и `SkillPicker` используют одинаковые подписи и высоту контролов 44 px. `AdminFieldGrid` выравнивает подпись, контрол и сообщения в общих строках CSS subgrid, включая переносы текста. Новые фильтры, банк вопросов и шаблоны используют одну сетку. На мобильных устройствах разделы доступны в горизонтальном меню.

Проверки: Vitest (контракты, фильтры, границы пагинации, приватная загрузка файлов), TypeScript, ESLint, production build; браузерная проверка на синтетических данных для десктопа, планшета и телефона. Проверка не меняет рабочие компании, пользователей или публикации.

При запуске второго dev-сервера обязательно задавайте отдельный `FSP_DEV_DIST_DIR`, например `FSP_DEV_DIST_DIR=.next-preview npm run dev -- --port 5186`. Два сервера с одной `.next-dev` перезаписывают модули и кеш друг друга. Production build использует отдельную `.next`.
