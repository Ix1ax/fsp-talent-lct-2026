# Защита несохранённого ввода

Общий реестр `shared/hooks/unsavedChangesGuard.ts` объединяет изменённые формы.
Перед уничтожением ввода используется одно браузерное подтверждение. Reload,
закрытие вкладки и уход в другой документ защищает нативный `beforeunload`.
Отказ сохраняет форму и возвращает фокус на элемент до начала перехода.

## Перечень форм

| Форма                                     | Предыдущий dirty-state / защита            | Текущая защита                                                                                    |
| ----------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| Профиль кандидата                         | RHF `isDirty`, ссылки / unload             | Сравнение нормализованного payload с defaults; общая защита                                       |
| Контакты кандидата                        | RHF `isDirty`, ссылки / unload             | Сравнение нормализованных контактов; автоматические имя/email не делают форму dirty               |
| Добавление навыка                         | RHF `isDirty`, ссылки / unload             | Нормализованный ввод; снятие защиты после успешного добавления                                    |
| Опыт работы                               | RHF без защиты                             | Payload опыта; Отмена / ссылки / история / unload                                                 |
| Образование                               | RHF без защиты                             | Нормализованные строки и год; Отмена / ссылки / история / unload                                  |
| Фото кандидата                            | Выбранный файл / редактор, ссылки / unload | Общая защита; шаги сохраняют файл; отмена изменённой обрезки требует подтверждения                |
| Импорт резюме                             | `applied` или `pending`, ссылки / unload   | Выбранный файл / pending до применения; применённые записи защищают собственные формы             |
| Импортированные опыт, образование, навыки | Предзаполненные defaults без dirty         | Несохранённый импорт считается черновиком; сохранение / удаление снимает защиту конкретной записи |
| Потребность работодателя                  | RHF `isDirty`, локальный диалог и unload   | Нормализованный ввод; локальная отмена, смена потребности/компании, ссылки и история              |
| Компания работодателя                     | RHF `isDirty`, локальный диалог            | Нормализованный ввод; закрытие Sheet, Escape, клик вне, ссылки / история / unload                 |
| Задание админки                           | RHF без защиты                             | Нормализованные editable defaults; Отмена / ссылки / история / unload                             |
| Шаблон админки                            | RHF без защиты                             | Defaults с составом теста; Отмена / ссылки / история / unload                                     |
| Справочник админки                        | RHF без защиты                             | Закрытие модалки, Escape, клик вне, смена справочника, уход со страницы                           |
| Аккаунт админки                           | RHF без защиты                             | Общая защита модалки; пароль сравнивается точно, email нормализуется                              |
| Модерация навыка                          | RHF без защиты                             | Причина/целевой навык; общая защита модалки                                                       |
| Предпросмотр теста админки                | Различие ответов, только unload            | Общая защита при наличии изменённых ответов                                                       |

Логин, поисковые фильтры, подтверждения удаления/архивации и согласий не являются
редакторами сохраняемых черновиков. Для них дополнительного dirty-state нет.
Истечение сессии остаётся принудительным завершением авторизации.

## Какие переходы сохраняют ввод

Layout `candidate/(profile)` сохраняет все секции профиля смонтированными:
`/candidate`, `/candidate/consents`, `/candidate/profile`, `/candidate/contacts`,
`/candidate/experience`, `/candidate/education`, `/candidate/skills`,
`/candidate/readiness`. Эти переходы, включая Back/Forward и программные кнопки
шагов, не требуют подтверждения. Уход на assessments, guides или другой маршрут
уничтожает layout и требует подтверждения. Reload не сохраняет черновики.

Показ подборки и открытие настроек компании сохраняют редактор потребности.
Открытие другой потребности, смена компании/вкладки списка и выход из кабинета
уничтожают редактор. Закрытие редактора компании уничтожает только его ввод,
не черновик потребности под ним.

Редакторы админки живут на конкретном маршруте или в модалке. Переход в карточку,
раздел или закрытие модалки уничтожают их состояние. В предпросмотре переключение
вопроса сохраняет локальные ответы.

## Правила для новых редакторов

- Используйте `useFormUnsavedChanges(form)` с нормализатором API, если у формы
  специальная нормализация. Не нормализуйте значимые пробелы пароля.
- Перед локальной отменой вызывайте `unsaved.discard(onClose)`. Во время сохранения
  отмена заблокирована. Escape, закрывающий крестик и клик вне должны использовать
  тот же обработчик.
- После успешного сохранения сбросьте RHF defaults и вызовите `unsaved.markSaved()`
  до программного перехода. После ошибки не сбрасывайте значения/defaults.
- Для программной навигации используйте `useGuardedRouter`; сами history API
  вызовы служат обновлению URL/индекса и не должны подменять проверку до смены React tree.
- `preserveWithin` разрешён только для маршрутов, на которых редактор действительно
  остаётся смонтированным. Ссылки с target/download и hash-ссылки не уничтожают ввод.
- Реестр устанавливается на уровне root layout, сохраняет индекс history вместе
  с состоянием Next и возвращает исходную запись при отказе от Back/Forward.
  Снятие защиты одной формы не снимает защиту остальных. Root cleanup удаляет
  обработчики и восстанавливает history methods.
- Подтверждённый logout проверяет черновики до завершения сессии и разрешает
  один последующий unload, без второго диалога. Ошибка logout сохраняет защиту.

## Проверки

`npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.
Для локального браузерного сценария используйте `scripts/review/unsaved-input.mjs`
с тестовым API и Chrome CDP, как в `browser-baseline.mjs`. Скрипт проверяет
ссылки/Отмену, Back/Forward, reload, Escape/клик вне, фокус, ошибку и повторное
сохранение справочника, сохранение после успеха без предупреждения, шаги кандидата
и несколько изменённых форм. Все запросы направляются только на loopback.
