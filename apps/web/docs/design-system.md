# Общие UI-компоненты и токены

Обычные продуктовые страницы используют компоненты из `shared/ui` и цвета из
`src/app/globals.css`. Компоновка лендинга и специальных интерактивов сохраняется.

## Контролы

| Задача               | Компонент                                      |
| -------------------- | ---------------------------------------------- |
| Действие             | `Button`, с явным `type="button"` внутри формы |
| Текст и число        | `Input`                                        |
| Многострочный текст  | `Textarea`                                     |
| Подтверждение        | `Checkbox`, с `Controller` для React Hook Form |
| Один ответ из группы | `Radio`, одинаковый `name` для всей группы     |
| Выбор из списка      | `OptionSelect` или существующий `Select`       |
| Файл                 | `FileInput`                                    |
| Диапазон             | `Slider`                                       |

`Radio` сохраняет нативную навигацию стрелками. Группа включается в Tab-порядок
один раз; подпись оборачивает контрол либо связана через `htmlFor`. Не заменяйте
это поведение независимыми кнопками ради визуального сходства.

Специальные карточки выбора типа/сложности задания, кнопки отметки верного ответа,
кликабельные заголовки вакансий и карточка добавления компании сохраняют свою
разметку. Это составные элементы, у которых уже есть семантика, фокус и disabled.
Нативные элементы внутри общих примитивов, скрытые поля формы и контролы игровых
визуализаций лендинга допустимы. Новые обычные поля за пределами `shared/ui`
проверяет `consistency/shared-controls`.

## Цвета и размеры

Используйте `background`, `foreground`, `card`, `muted`, `muted-foreground`,
`border`, `input`, `primary`, `primary-foreground`, `brand-text`, `destructive`,
`success`, `success-soft`, `success-foreground`, `warning`, `warning-soft`.
Семантические цвета имеют значения для обеих тем. Не подменяйте их `red-500`,
`white` или значением hex в продуктовых компонентах.

Для действий поверх фотографии используются `media-overlay` и
`media-foreground`: они сохраняют контраст независимо от темы и цвета снимка.
Белый фон при экспорте JPEG в `cropAvatar` относится к содержимому файла,
а не к оформлению страницы. Фирменные SVG/паттерны и интерактивные визуализации
лендинга сохраняют свою палитру; графики статистики уже используют CSS-токены.

| Элемент                     | Радиус / отступ            |
| --------------------------- | -------------------------- |
| Бейдж                       | `rounded-sm`               |
| Токен брифа, пункт меню     | `rounded-md`               |
| Кнопка, поле, строка списка | `rounded-lg`               |
| Карточка                    | `rounded-xl`, `p-5 sm:p-6` |
| Заголовок страницы, диалог  | `rounded-2xl`              |
| Основной контрол            | 40 px (`h-10`)             |
| Компактный контрол списка   | 32 px (`h-8`)              |

Обычная страница собирается через `PageWrapper` и compound `PageHeader`.
Круглые аватары и круглые специальные элементы сохраняют `rounded-full`.
Не вводите промежуточные радиусы и отдельные контейнеры для очередной страницы.

## Props и защита правил

Props с собственными полями оформляются как `interface ComponentNameProps`.
Если компонент только наследует props примитива, используйте
`type SliderProps = ComponentProps<typeof SliderPrimitive.Root>` без пустого
interface. Остальные данные оформляются через `type`; декларации библиотечных
модулей в `.d.ts` сохраняют необходимые интерфейсы.

ESLint проверяет стрелочные функции, именование props, явный return компонентов,
пустые catch (включая комментарии и callbacks `.catch()`), вложенные тернарники,
публичные импорты, обычные контролы и семантические цвета. Правило API требует
`const { data } = await clientApi.get(...); return data;` для известных Axios
клиентов `clientApi`, `serverApi`, `publicServerApi`; запрос без результата можно
просто `await`-ить. Fetch и административный клиент сохраняют свой контракт.

`npm run lint` также запускает проверки правил из
`scripts/eslint/consistency.test.mjs`. Тесты проверяют разрешённые случаи:
наследуемые props, методы классов, App Router handlers, запросы без тела ответа
и нативные контролы внутри общих примитивов.
