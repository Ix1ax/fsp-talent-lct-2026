# API и авторизация

## Клиенты и прокси

Браузерный `clientApi` из `shared/api/client.ts` использует `/api` по умолчанию.
В API-функциях пути начинаются с `/v1`: запрос `/v1/me/profile` отправляется как
`/api/v1/me/profile`. Next.js проксирует его на `API_PROXY_TARGET`.
Локальные обработчики `/api/auth/session`, `/api/auth/refresh` и `/api/auth/logout`
управляют веб-сессией.

Серверные `serverApi` и `publicServerApi` определены в `shared/api/server.ts`.
Они обращаются напрямую к `${API_PROXY_TARGET}/api`; `serverApi` добавляет
access token из серверной cookie. `publicServerApi` используется для общедоступных
справочников. Не используйте браузерный клиент для загрузки данных серверной страницы.

Общий Axios-клиент преобразует JSON и параметры из camelCase в snake_case,
ответы — обратно. `FormData` собирается явно: имена полей должны совпадать с API.
Ошибки приводятся к `ApiError`. Админский клиент использует отдельный транспорт
и схемы Zod, сохраняя контракт snake_case.

## Сессии

Вход кандидата и работодателя использует OIDC/Keycloak. После callback веб-сессия
сохраняется через серверный обработчик. Access и refresh tokens находятся
в HttpOnly cookies; клиентский access token хранится в памяти.
`AuthBootstrap` восстанавливает сессию, браузерный клиент координирует обновление
токена, серверные страницы проверяют пользователя через `requireRole`.
Временная недоступность API и отсутствие авторизации — разные состояния.

Администратор входит через `/admin`, используя `/api/v1/admin/auth/*`.
Его сессия хранится отдельно в sessionStorage текущей вкладки.
Пользовательский OIDC-токен не заменяет админскую сессию.
Подробности: [ADMIN.md](../ADMIN.md).

## Где находятся интеграции

| Область                                        | Реализация                                                    |
| ---------------------------------------------- | ------------------------------------------------------------- |
| Пользователь и регистрация роли                | `entities/session/api`                                        |
| Справочники и поиск навыков                    | `entities/catalog/api`                                        |
| Профиль, анкета, аватар и PDF                  | `entities/candidate/profile/api`                              |
| Контакты, согласия, опыт, образование и навыки | Соответствующие сегменты `entities/candidate`                 |
| Импорт резюме и данные ФСП                     | `entities/candidate/resume/api`, `entities/candidate/fsp/api` |
| Тестирование и история                         | `entities/assessment/api`                                     |
| Компании, документы, участники и верификация   | `entities/company/api`                                        |
| Потребности и подбор кандидатов                | `entities/employer-need/api`, `entities/employer-bank/api`    |
| Приглашения кандидата                          | `entities/candidate-offers/api`                               |
| Задания компаний и решения                     | `entities/company-task/api`                                   |
| Админка и предпросмотры                        | `entities/admin/api`, `features/admin`, `screens/admin`       |

Справочники специализаций и грейдов содержат числовые ID, навыки — строковые.
Для отображения названий сопоставляйте ID с актуальным справочником. Не выводите
специализацию и грейд без стека в названиях доступных тестов.
Ошибку загрузки справочников показывайте пользователю с возможностью повторить запрос.

## Контракт

Swagger доступен на `/docs/` бэкенда, схема — на `/openapi.yaml`.
Документация API и инфраструктуры находится в корне монорепозитория и в `apps/api`.
При расхождениях проверяйте схему именно запущенного сервера: локальные копии
OpenAPI могут отличаться от развёрнутой версии.

Настройка proxy не подтверждает интеграцию сама по себе: для нового метода нужны
API-функция, вызывающий её сценарий, состояния загрузки/ошибки и проверка контракта.
Служебные `/healthz` и `/readyz` проксируются Next.js для проверки API и зависимостей.
Интерфейс описывает интеграцию ФСП как работу с тестовым реестром; не обещайте
подтверждение реального идентификатора без проверки соответствующего бэкенда.
