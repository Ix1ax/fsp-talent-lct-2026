# Справочники админки

`useAdminOptions` принимает явный список справочников. Список шаблонов и редактор
загружают только специализации и грейды. Каждый справочник имеет собственные
`data`, `loading`, `error` и повторную загрузку. Ошибка одной страницы исключает
частичный список из результата, но не мешает другому справочнику.

Полная загрузка выполняется страницами по 100 записей с максимальным offset
10 000, согласно существующему контракту API. Полная последняя страница без
`total` не доказывает завершение: в этом случае возвращается явная ошибка лимита,
а не 10 100 записей под видом полного справочника. Если API сообщает точный
`total`, полный список из 10 100 записей допустим. Короткая страница при большем
`total` тоже считается ошибкой.

Навыки не скачиваются целиком. `SkillPicker` использует серверный `q`, debounce
300 мс и выдачу до 50 записей. Клиентская фильтрация Command отключена. Выбранное
значение загружается отдельно по ID и сохраняет подпись при смене поисковой
выдачи. Архивный или неодобренный выбранный навык помечается недоступным; 404
отображается как ошибка, при этом ID не стирается из формы. Редакторы выбирают
только активные одобренные навыки, фильтры списков допускают архивные значения.
При объединении модерация проверяет доступность целевого навыка перед отправкой.

Кеш существует в памяти текущей admin-сессии и ограничен 200 завершёнными
записями запросов. Ключ страницы включает вид справочника, строку поиска, limit
и offset; полная загрузка и запрос выбранного навыка также кешируются. Навыки
из поисковой страницы заполняют кеш отдельных значений. Совпадающие запросы
объединяются, независимо от числа списков и редакторов. Отмена одного ожидания
не прерывает запрос остальных; отмена последнего ожидания освобождает транспорт.
Немедленное повторное подключение в Strict Mode сохраняет общий запрос.

Создание, изменение, архивирование и удаление сбрасывают кеш своего справочника
после успешного ответа. Модерация сбрасывает кеш навыков. Подписанные компоненты
перечитывают данные. Ошибки не кешируются как успешные результаты. Logout,
истечение сессии и новый токен очищают все записи и отменяют запросы; поздний
ответ старого запроса не заполняет новый кеш. Поздний `adminMe` после logout
не восстанавливает старую сессию.

Проверки: `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.
Браузерный сценарий: `node scripts/review/admin-options.mjs` с локальными
mock API на 5191, приложением на 5185 и Chrome CDP на 9224. Адреса можно задать
через `REVIEW_API_URL`, `REVIEW_APP_URL`, `REVIEW_CDP_URL`; допустимы только
loopback-хосты. Сценарий проверяет поиск, сохранение выбранной подписи, отмену
устаревшего результата, повторное использование между списком и редактором,
независимые ошибки и маршруты через HTML/RSC.

Исправление маршрутов независимо от этой загрузки: только
`src/app/admin/[section]/page.tsx` и соседний `__tests__/page.test.ts` относятся
к задаче №6. Проверка собственных ключей сужает строку до типа допустимых
разделов до выбора компонента. Неизвестные строки и имена свойств прототипа
передаются в `notFound()`.
