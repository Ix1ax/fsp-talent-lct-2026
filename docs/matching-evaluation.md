## Результаты

| Сценарий | Ожидаемый и фактический порядок | Покрытие стека |
|---|---|---|
| Junior, Go обязателен, SQL необязателен | anna → boris → kirill → vera | 100 → 87,5 → 75 → 62,5 |
| Junior, Go и SQL обязательны | anna → boris → vera | 100 → 87,5 → 62,5 |
| Только Middle, оба навыка обязательны | dina | 100 |
| Грейд не ограничен, оба навыка обязательны | anna → dina → boris → vera | 100 → 100 → 87,5 → 62,5 |
| Только Senior, оба навыка обязательны | Пустая выдача | — |

Пять сценариев совпали с ожидаемым порядком и `total`. Проверены все 12 позиций через отдельные страницы `limit=1`; порядок и общее количество сохраняются. Посторонний работодатель получает 404 во всех пяти сценариях. Ответ содержит `Cache-Control: private, no-store`, источники навыков и объяснения; самооценка не выдаётся за подтверждение тестом.

Покрытие стека считается как `100 × Σ(вес × коэффициент) / Σ(вес)`: тест — 1, самооценка — 0,5, отсутствие — 0. Это прозрачное правило ранжирования, а не вероятность найма. Все обязательные навыки должны присутствовать; самооценка допускается, но явно отмечается.

Без требований к стеку оценка равна `null`. При равном покрытии учитываются результат теста категории, совпадения условий, затем UUID. Эти правила и отсутствие утечки контактов отдельно проверяются в `candidate_matching_integration_test.go` и `candidate_recommendations_integration_test.go`.

## Повторный запуск

Нужен отдельный PostgreSQL для тестов. На рабочий сервер этот набор загружать не нужно.

```bash
TEST_DATABASE_URL='postgres://user:password@localhost:5432/fsp_test?sslmode=disable' make matching-evaluation
```

Тест создаёт временную схему, применяет миграции, загружает набор и удаляет схему после завершения. Команда требует явный `TEST_DATABASE_URL`, чтобы не использовать рабочие настройки по умолчанию. `-count=1` исключает кэш результатов, `-race` проверяет выполнение с детектором гонок.

## Границы проверки

Результат означает соответствие заданным правилам на этом наборе. Он не доказывает качество найма на реальных кандидатах. Коэффициент самооценки 0,5 ещё не калиброван на реальных данных; проценты разных шаблонов тестирования не нормализованы по сложности. Если работодателю нужен конкретный уровень, следует задавать грейд потребности.

Достижения ФСП пока не участвуют в ранжировании и остаются в `unassessed_criteria`. Их влияние и привязку ФСП ID нужно проверить отдельным набором после реализации. Реальные результаты найма и отзыв работодателей также требуют отдельной оценки.
