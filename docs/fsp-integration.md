# Привязка ФСП и достижения

Реального API ФСП в хакатоне нет. Адаптер `fsp/registry/Mock` возвращает собственные синтетические данные с источником `fsp_mock`. Вход через Keycloak сам по себе не импортирует достижения. Эта демонстрационная привязка не подтверждает владение реальным ФСП ID.

## Сценарий фронта

1. Кандидат создаёт профиль и даёт согласие processing.
2. `GET /api/v1/me/fsp` возвращает `{ "link": null, "items": [] }` до привязки.
3. Кнопка привязки вызывает `POST /api/v1/me/fsp/link` без тела с access token. Сервер использует проверенную пару issuer + subject, произвольный ID от клиента не принимается.
4. `POST /api/v1/me/fsp/sync` обновляет полный снимок достижений. Повторный запрос не создаёт дубли.
5. `DELETE /api/v1/me/fsp` удаляет привязку и её достижения; тестовый грейд не меняется. Удаление разрешено и после отзыва processing.

`sync_status`: ready — есть достижения, empty — история пуста, unavailable — обновление не удалось. При ошибке реестра API возвращает 503, ранее сохранённые данные остаются. Без привязки sync возвращает 409. Без профиля или согласия чтение и импорт возвращают 403.

## Тестовый реестр

SHA-256 пары issuer + subject определяет стабильный участник mock и один из трёх сценариев: призовое место, участие, отсутствие истории. Сценарий не выбирается запросом клиента. Для реальной интеграции нужно заменить адаптер и установить проверенную связь внешней идентичности с участником реестра; текущий hash не является такой проверкой.

## Отображение работодателю

Достижения доступны в полном собственном профиле и в разрешённых деталях кандидата работодателю. В карточке банка — achievements_count и fsp_bonus. Внешний participant_id в ответ работодателю не передаётся. Действуют существующие проверки роли, членства в компании, статуса профиля и согласий processing/publication.

Бонус по лучшему результату: места 1–3 дают 5, другие места — 3, участие — 1. Без подтверждённой тестом категории бонус 0. При сортировке бонус влияет только на порядок внутри одной подтверждённой специализации и грейда; позиции других категорий сохраняются. В подборке он добавляется к сходству для сортировки, в свободном банке — к результату теста. Сам match_score, грейд и подтверждения навыков не меняются. Это политика демонстрации, численные веса ТЗ не задаёт.

Фильтр has_fsp_achievements=true оставляет профили с достижениями, false — без них. Без параметра доступны оба варианта.

## Запуск и проверка

Новая миграция создаёт fsp_links и fsp_achievements; прежние профили и категории сохраняются. Новых переменных окружения нет. Схема требует применения миграции перед запуском нового API. Автотесты проверяют стабильность mock, импорт без дублей, пустую историю, сохранение данных при сбое источника, приватность, фильтры и ранжирование. Реальный реестр и реальная привязка ФСП ID остаются будущей интеграцией.
