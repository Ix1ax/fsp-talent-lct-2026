# Работа в команде

1. Создайте ветку от `main`: `feat/candidate-profile`, `fix/invitation-status` и т.п.
2. Согласуйте новый метод в `api/openapi.yaml`, затем меняйте обработчик и фронт.
3. Добавьте миграцию с новым номером в `apps/api/migrations`. Уже применённые миграции не редактируем.
4. Запустите `make check`, а для изменений инфраструктуры — `make up && make smoke`.
5. Откройте PR с описанием результата и проверки. В `main` стоит включить обязательные проверки `backend`, `frontend`, `integration` и хотя бы один review.

Комментарии пишем на русском: объясняем нетривиальное правило или причину решения. Не пересказываем очевидную строку кода. Имена Go/TS сущностей, протоколы и служебные директивы остаются на английском.

## Миграции

```sh
make migrate
cd apps/api
set -a; . ./.env; set +a
go run ./cmd/migrate status
```

Миграции выполняются отдельным процессом. Новые миграции по возможности совместимы с предыдущей версией API: сначала добавление, затем перенос данных, удаление — отдельным релизом. Откат `go run ./cmd/migrate down` может удалить данные; не использовать как автоматическую реакцию на неудачный деплой.

## Конфигурация

Примеры `.env.example` содержат только локальные значения. Реальные `.env` исключены из Git и Docker build context. Не коммитим ключи, токены, дампы с персональными данными и материалы кандидатов. Для тестовых данных используем синтетические профили.

Настройки Go: `APP_ENV`, `HTTP_ADDR`, `DATABASE_URL`, `REDIS_ADDR`, `REDIS_PASSWORD`, `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`, `OIDC_ISSUER`, `OIDC_CLIENT_ID`. Все обязательные значения перечислены в `apps/api/.env.example`; в production OIDC обязателен.

## Контракт ошибок

HTTP-ошибки: `{"error":{"code":"unauthorized","message":"…"}}`. В ответах не возвращаем SQL, DSN, внутренние ошибки SDK или stack trace. `X-Request-ID` помогает сопоставить ответ с JSON-логом. Readiness возвращает только общий статус, подробности инфраструктуры не раскрывает.

## Фронтенд

```sh
npm run dev
npm run lint
npm run typecheck
npm run build
```

Зависимость фронта добавляем из корня: `npm install <package> -w apps/web`. Пока есть только стартовая страница и типизированная функция `getAPIInfo`; роутер и менеджер серверного состояния добавим с первыми кабинетами.
