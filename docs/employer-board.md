# Кабинет работодателя

Рабочие разделы `/employer` используют общие карточки, кнопки, поля, диалоги, темы и семантические токены приложения. Композиция компаний и потребностей основана на Hirify: компактная верхняя навигация, широкая область содержимого, каталог компаний и лента потребностей с фильтрами слева. Пошаговое создание компании и потребности, сохранение форм и защита черновиков сохраняют флоу кабинета соискателя.

Кабинет без компаний центрирует заголовок и две карточки: создание компании и принятие приглашения. На телефоне карточки располагаются друг под другом; пустого переключателя компаний нет. Создание компании и отдельная страница приглашения имеют ограниченную ширину и располагаются по центру. Переключение разделов и шагов потребности возвращает прокрутку к началу нового содержимого; черновики сохраняются.

`/employer` показывает все доступные компании сеткой карточек: название, описание, роль, статус проверки и основная кнопка «Банк соискателей» и ссылки на профиль, документы, сотрудников и потребности. В разделах переключатель компании остаётся в заголовке; навигация компании располагается горизонтально на компьютере, а на телефоне и планшете доступна через Select. Документы, сотрудники и пошаговые формы ограничены по ширине.

Профиль компании открывается в режиме просмотра по композиции страницы компании Hirify: слева логотип, статус проверки, контакты и реквизиты, справа описание и до трёх активных потребностей с переходом к полному банку. Владелец открывает форму отдельной кнопкой «Редактировать». Сохранение возвращает к обновлённому профилю; отмена предупреждает о несохранённых изменениях. На телефоне заголовок и кнопка редактирования идут первыми, а в режиме ввода карточка с контактами скрывается. Сайт компании отображается ссылкой только для HTTP(S) без встроенных учётных данных.

Раздел потребностей имеет поисковую строку, статусы, сортировку, отдельную панель специализации, грейда, навыка и форматов работы. На мобильном экране фильтры раскрываются кнопкой. Карточки показывают зарплату, формат, специализацию, навыки и статус; данные загружаются из API выбранной компании. Фильтрация и сортировка по зарплате сначала читают все страницы выбранного статуса, затем фильтруют полный список и разбивают результат на страницы. При ошибке или превышении допустимого объёма частичные результаты не выдаются за полную подборку.

## Сценарии

- `/employer/profile`: просмотр компании, отдельный режим редактирования, контакты, ИНН с контрольной суммой, статус проверки только для чтения. Редактировать может owner. Создание компании сохраняет переход к документам; редактирование возвращает в просмотр.
- `/employer/documents`: логотип, документы, проверка форматов/размеров/числа пикселей, multipart-загрузка, защищённое blob-скачивание, удаление. Только owner изменяет файлы.
- `/employer/team`: активные и отключённые сотрудники, смена recruiter/viewer, отключение, создание и отзыв приглашений, копирование ссылки. API не возвращает имена сотрудников: показывается локальный UUID.
- `/employer/invitation?token=…`: принятие приглашения; вход и выбор роли сохраняют безопасный маршрут возврата. Email получателя проверяет сервер. Автоматической отправки письма нет.
- `/employer/vacancies`: поиск потребностей компании, активные/черновики/архив, создание, редактирование, копирование, архивирование и восстановление. Форма: роль и задачи → условия → навыки → готовность. Новая потребность сначала сохраняется в draft; active требует навыки и форматы работы.
- `/employer/candidates`: поддерживаемые API-фильтры в боковой панели, выбор активной потребности с применением её условий, обезличенная карточка, навыки/квалификация, опыт, образование, достижения ФСП.
- `/employer/offers`: история и статусы предложений, подробные условия, отдельный запрос контактов после accepted. Отправка доступна owner/recruiter из карточки кандидата или подборки активной потребности.

Формы компании, приглашения сотрудника и потребности остаются смонтированными при переключении разделов, поэтому черновики сохраняются. Смена компании и закрытие редактируемой потребности предупреждают о потере изменений. POST предложений не повторяется автоматически после сетевой ошибки: пользователь сначала проверяет историю.

## Контракты и архитектура

`entities/company` содержит профиль, файлы, команду и приглашения; `entities/employer-need` — потребности и рекомендации; `entities/employer-bank` — обезличенные кандидаты и предложения. `features` отвечают за действия пользователя; `screens/employer` связывает API, выбранную компанию и навигацию. Кабинет использует только рабочий API: компании, потребности, команда, файлы и предложения сохраняются на сервере. Доступ к маршрутам требует действующую сессию работодателя; ошибки API показываются пользователю без подмены данных.

API использует `/v1/...` поверх общего `clientApi` с baseURL `/api` и преобразованием camelCase/snake_case. Массивы PATCH потребности заменяются полностью. Метаданные ответа не отправляются в запись. Форматы банка передаются CSV-строкой; флаг проверки навыка — только вместе со skillId.

Списки компаний, файлов, команды, приглашений, потребностей и предложений не имеют total: UI не показывает вымышленные общие счётчики. Банк кандидатов и рекомендации используют серверный total. Чтения отменяются через AbortController; данные, ошибки и персональные контакты не смешиваются между компаниями. Контакты кандидата живут только в памяти открытой карточки предложения.

Подборка показывает серверные оценки совпадения, причины, неизвестные критерии, подтверждённые/заявленные/отсутствующие навыки. Match score означает сходство с требованиями, а не вероятность найма. Самооценка грейда отличается от подтверждения тестом; null-результат не отображается как 0%.

«Потребности» — потребности выбранной компании (`needs`). Адрес `/employer/vacancies` сохранён для совместимости ссылок. Публичный банк для соискателей и отклики на публичные потребности требуют новых backend-маршрутов. API также не предоставляет удаление компании, передачу владения, отмену предложений или агрегированную аналитику.

## Проверка

Из корня: `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`. Тесты включают транспорт файлов/членства/приглашений, валидацию ИНН/ссылок/зарплат, фильтры, размеры изображений и сохранение приглашения при входе.

Для параллельного проверочного dev-сервера в `apps/web` можно использовать `FSP_DEV_DIST_DIR=.next-preview npx next dev --hostname 127.0.0.1 --port 5187`. Отдельный каталог сборки предотвращает конфликт кешей с основным сервером; production продолжает использовать `.next`. Верстка проверена в браузере на ширинах 390, 768 и 1440 px, включая все шесть разделов и длинное название компании.

Для локальной работы скопируйте `apps/web/.env.example` в `apps/web/.env.local`: `API_PROXY_TARGET` указывает на API, а `OIDC_TOKEN_URL` и `OIDC_CLIENT_ID` обеспечивают обновление сессии через Keycloak. Вход выполняется через `/login`, кабинет — `/employer`. Все разделы используют серверные данные; незавершённые формы остаются черновиками до сохранения.

Frontend-проверки: 429 тестов, typecheck, lint и production-сборка прошли. Демо-маршрут удалён (404); API компаний без авторизации возвращает 401. Настроен локальный Keycloak и проверен переход из `/employer` на настоящий OIDC-вход. Редирект обновления сессии сохраняет исходный адрес сайта, включая `localhost` при привязке сервера к `0.0.0.0`. На локальном окружении прошли `TestCompaniesAndPrivateS3` и `TestCompanyNeeds`: они используют отдельные временные схемы БД и очищают свои файлы в S3. Проверены доступность API, OIDC и прокси фронта; OpenAPI запущенного сервера содержит методы команды, банка и предложений. Через браузер на существующем аккаунте работодателя проверены создание компании, сохранение профиля, загрузка списка сотрудников, создание и отзыв приглашения, создание потребности по четырём шагам, редактирование условий/навыков, активация, подбор, архив и восстановление в черновик. Проверочная потребность оставлена в архиве, приглашение отозвано. Копирование одноразовой ссылки не проверено: к моменту разрешения сессия истекла и ссылка исчезла после повторного входа.

В банке соискателей проверены запрос к локальному API, сочетание фильтров навыка/подтверждения/форматов, дробный опыт, неверный диапазон и сброс. Дробный ввод опыта сохраняется в поле без пересчёта отображаемого значения после каждого символа. API возвращает 0 доступных соискателей: реальные карточки, отправку предложений и получение контактов пока проверить не на ком. Смена роли и отключение другого сотрудника также не проверены на живом аккаунте, поскольку в проверочной компании только владелец.

Каталог компаний и обновлённый раздел потребностей проверены на ширинах 390, 768 и 1440 px: горизонтального переполнения нет. Проверены переходы из карточки компании, совместная работа поиска/специализации/навыка/формата, пустой результат и сброс, сортировка, открытие архивной потребности и предупреждение при закрытии несохранённого черновика. При восстановлении истёкшей сессии защищённый layout загружается заново после обновления cookie; ошибка API показывает возможность повторить запрос вместо пустого экрана. URL выбранной компании/потребности синхронизируется только при явных действиях, чтобы не отменять переход после сохранения профиля.

Режим просмотра профиля проверен на 390, 768, 946 и 1440 px. Через локальный API проверены отдельная кнопка редактирования, отмена с предупреждением, сохранение с возвратом в просмотр, сохранность данных после перезагрузки и переход в раздел потребностей выбранной компании. Проверочное описание возвращено к исходному. Тесты проверяют отсутствие формы в режиме просмотра, доступ к кнопке редактирования только для владельца, экранирование описания и запрет небезопасных контактных ссылок.

В банке соискателей фильтры находятся слева на компьютере и раскрываются кнопкой на телефоне и планшете. Выбор активной потребности подставляет специализацию, грейд, бюджет и форматы; серверная подборка учитывает все навыки, город и часовой пояс. Изменение любых эффективных условий поиска снимает привязку и использует общий банк. Полное возвращение исходных условий восстанавливает ранее выбранную потребность; порядок форматов и пустые значения не влияют на сравнение. Явный сброс забывает выбранную потребность. Архив и черновики не доступны для подбора.

Селекты кабинета используют общий `OptionSelect` на базе Radix/shadcn: меню, клавиатура, пустой вариант и значения форм сохраняют семантику приложения. Проверены мобильный выбор, клавиатурное управление, снятие/восстановление привязки и переход из основной кнопки карточки компании в банк соискателей. Проверочная потребность снова архивирована. Справочник не изменён.
