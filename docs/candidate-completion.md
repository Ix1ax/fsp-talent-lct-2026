# Кандидат: первичный путь и тестирование

## Работа фронта

1. Войти через Keycloak и выбрать роль candidate.
2. Дать согласие processing, создать профиль, заполнить контакты и резюме.
3. PUT /api/v1/me/profile/onboarding сохраняет industry (отрасль свободным текстом), specialization_id, grade_id (самооценка) и soft_skills (до 20 уникальных названий). ID берутся из общих справочников. Опрос не меняет подтверждённую категорию.
4. GET /api/v1/me/profile/onboarding или /me/profile/full возвращает next_step: consent, profile, survey, test, in_progress, complete. Для активной попытки есть её ID и дедлайн. Для истёкшей попытки вызовите GET /api/v1/me/assessments/attempts/{id}, чтобы получить итог; повторное чтение безопасно.
5. GET /api/v1/me/assessments/available сообщает доступные пары, can_start, reason и retry_at. Архивированные справочники не предлагают новые тесты. При недостатке активных вопросов can_start=false, reason=assessment_unavailable; старт также проверяет доступность в транзакции.
6. POST /api/v1/me/assessments/attempts начинает тест. Один активный тест на кандидата; сервер сохраняет неизменяемые вопросы, проверку, время и порог. PUT /attempts/{id}/answers/{question_id} сохраняет/заменяет ответ до завершения. POST /attempts/{id}/submit оценивает его; повтор возвращает тот же итог.
7. GET /api/v1/me/assessments/history?limit=20&offset=0 возвращает собственные попытки, баллы и присвоенные категории. Полный итог отдельной попытки доступен по её ID. В истории и активном тесте правильные ответы не раскрываются.
8. GET /api/v1/me/profile/export.pdf скачивает стандартное собственное резюме с кириллицей, переносами и страницами. Включены контакты, навыки, опыт, образование, отрасль, софт-скиллы, форматы работы, категория и достижения. Нужны профиль и processing; чужой ID не принимается.

Опрос доступен отдельно от прохождения; ранее существовавший старт теста по переданной паре остаётся совместимым. declared_category в банке использует опрос, а без него последнюю попытку. category по-прежнему задаётся только успешным тестом.

## Правила грейда и согласий

После успешного присвоения категории следующая смена доступна через **7 суток**. Это выбранная политика команды, ТЗ не задаёт численный интервал. Ограничение общее для смены специализации и повышения грейда, проверяется под блокировкой кандидата. reason=grade_change_cooldown и retry_at объясняют запрет старта. Итог попытки содержит next_grade_change_at; до первого успеха null.

Пересдача проваленной пары отдельно ограничена ASSESSMENT_RETAKE_DAYS (существующая настройка, по умолчанию 7). После первичного провала можно попробовать другую, более низкую пару. Уже подтверждённый или более низкий уровень той же специализации не пересдаётся. Провал не меняет текущую категорию и не понижает подтверждения навыков.

При отзыве processing запрещены новый тест, ответы, активное завершение, изменение опроса и PDF. История собственных попыток остаётся доступной; просроченные попытки закрываются, но новые категория и подтверждения не присваиваются. В onboarding опрос и последняя попытка скрыты до восстановления согласия. Публикация и контакты работодателю продолжают проверяться отдельными согласиями и правилами предложения.

Если во время теста навык объединён с другим, подтверждение записывается целевому одобренному активному навыку. Снимок исходных вопросов не меняется. Архивированный/отклонённый навык не получает новое активное подтверждение; для следующих тестов администратор должен актуализировать шаблон и задания.

## Демобанк и проверка механики

Есть опубликованные Backend Junior/Middle и Frontend Junior/Middle. Middle содержит дополнительные вопросы по Go, SQL, TypeScript и React сложности 2. Порог Middle — 75%, время — 30 минут. Для каждой строки есть запас вопросов и случайная сборка. При наличии ранее созданного шаблона Middle миграция не заменяет его состав или публикацию.

Воспроизводимый прогон: TestAssessmentQualityEvaluation, по четыре варианта каждой пары для трёх профилей знаний:

| Профиль | Backend Junior | Backend Middle | Frontend Junior | Frontend Middle |
|---|---:|---:|---:|---:|
| Слабый: не решает задания | 0%, провал | 0%, провал | 0%, провал | 0%, провал |
| Средний: базовые знания; в backend также Go сложности 2 | 71,43%, успех | 50%, провал | 60%, успех | 0%, провал |
| Сильный: решает все задания | 100%, успех | 100%, успех | 100%, успех | 100%, успех |

Используются реальные случайные вопросы, API хранилища ответов, серверная проверка и запись категории. Четыре испытания выполняются на независимых кандидатах с одинаковым профилем знаний: продуктивные ограничения запрещают повторный старт уже подтверждённой пары. Это проверка различимости синтетических типов и устойчивости баллов при смене варианта, не доказательство валидности экзамена для реальных специалистов. Банк и пороги ещё требуют содержательной оценки команды; проценты между разными шаблонами не нормализованы.

## Миграции и запуск

Добавлены 20261008100001_candidate_onboarding.sql и 20261008100002_assessment_middle_bank.sql. Номера намеренно идут после уже существующей 20261008100000_candidate_career.sql; применённые миграции не переименованы. Изменения добавочные, старый API продолжает работать. Перед новым API применить миграции штатной командой migrate. Новых переменных окружения нет.

PDF генерируется внутри Go, шрифты встроены в бинарник с лицензией SIL OFL. На сервере не нужны браузер, LibreOffice или отдельный PDF-сервис. Файлы резюме не сохраняются в S3 при скачивании.
