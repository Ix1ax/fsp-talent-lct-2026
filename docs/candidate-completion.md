# Кандидат: выбор стека и тестирование

## Работа фронта

1. Войти через Keycloak, выбрать candidate, дать согласие processing и создать профиль.
2. GET /api/v1/me/assessments/available возвращает сочетания specialization_id, stack_skill_id, stack_name и grade_id с can_start, reason и retry_at. Выбор: специализация → основной язык или технология → грейд. Навыки резюме сами по себе не создают экзамен.
3. PUT /api/v1/me/profile/onboarding сохраняет industry, specialization_id, stack_skill_id, grade_id и soft_skills. Основной стек — UUID одобренного навыка общего справочника. Опрос не подтверждает категорию. Старый опрос без стека требует повторного выбора.
4. GET /api/v1/me/profile/onboarding или /me/profile/full возвращает next_step: consent, profile, survey, test, in_progress, complete. Активная попытка содержит ID и дедлайн. Для результата истёкшей попытки вызовите GET /api/v1/me/assessments/attempts/{id}.
5. POST /api/v1/me/assessments/attempts принимает specialization_id, stack_skill_id и grade_id. Стек обязателен; сервер не выбирает Go для Backend автоматически. Отсутствующий шаблон или нехватка вопросов дают 409 assessment_unavailable. available также показывает недоступность при нехватке вопросов; архивированный стек не предлагает новые тесты.
6. Сервер фиксирует вопросы, основной стек и его название, правила проверки, время и порог. PUT /attempts/{id}/answers/{question_id} сохраняет/заменяет ответ до завершения. POST /attempts/{id}/submit рассчитывает итог; повтор возвращает тот же результат. Один активный тест на кандидата.
7. GET /api/v1/me/assessments/history?limit=20&offset=0 возвращает собственные попытки, стеки, баллы и категории. Правильные ответы кандидату не раскрываются.
8. GET /api/v1/me/profile/export.pdf скачивает собственное резюме с кириллицей и переносами страниц. Включены контакты, навыки, опыт, образование, отрасль, софт-скиллы, форматы работы, все квалификации и достижения. Нужны профиль и processing; чужой ID не принимается.

Пример старта Backend / Java / Junior:

```json
{
  "specialization_id": 1,
  "stack_skill_id": "00000000-0000-4000-8000-000000000006",
  "grade_id": 2
}
```

Для Go UUID демонавыка заканчивается на 001, для JavaScript — на 002. Интерфейс использует ID из API. Для отсутствующего экзамена показываем «Тест для этого стека и уровня пока недоступен».

## Квалификации и ограничения

Успех требует проходного общего балла и проходного процента по основному навыку. SQL не компенсирует провал Java. Подтверждение Backend / Go / Junior не подтверждает Java.

category остаётся последней присвоенной категорией и содержит стек. qualifications в полном профиле и подробной карточке работодателя сохраняет лучший уровень отдельно по каждой специализации и стеку. Новое подтверждение не удаляет прежнее. Карточка работодателя содержит стек категории; список qualifications не раскрывает ID попыток и ответы. declared_category — самооценка из опроса, либо последней попытки при отсутствии опроса.

После успешного присвоения категории изменение грейда или специализации доступно через 7 суток. Это политика команды, ТЗ не задаёт численный интервал. Другой стек на том же грейде той же специализации можно подтвердить без ожидания отдельным тестом. reason=grade_change_cooldown и retry_at объясняют запрет; результат содержит next_grade_change_at. Проверки сериализованы блокировкой кандидата.

Пересдача проваленной тройки отдельно ограничена ASSESSMENT_RETAKE_DAYS (существующая настройка, по умолчанию 7). Провал Go не блокирует Java. После первичного провала можно попробовать более низкий грейд. Уже подтверждённый или более низкий уровень той же специализации и стека не пересдаётся. Онбординг учитывает более высокий подтверждённый уровень того же стека. Провал не понижает категорию и подтверждения навыков.

При отзыве processing запрещены новый тест, ответы, активное завершение, изменение опроса и PDF. Собственная история остаётся доступной. Просроченная попытка закрывается без присвоения новых категории и подтверждений. Опрос и последняя попытка в onboarding скрыты до восстановления согласия. Публикация и контакты работодателю проверяются отдельными согласиями и правилами предложения.

При объединении навыка во время теста подтверждение записывается целевому активному одобренному навыку. Исходные вопросы и название стека в снимке сохраняются. Архивированный или отклонённый навык не получает новое активное подтверждение; администратор актуализирует задания и шаблон для следующих тестов.

## Админка и демобанк

Администратор выбирает специализацию, основной навык и грейд, задаёт blueprint и публикует шаблон. Основной навык обязан входить в blueprint. Вопросы общих навыков переиспользуются. Версия и единственный опубликованный шаблон ограничены тройкой: новая версия Java не архивирует Go. GET /api/v1/admin/assessments/templates поддерживает stack_skill_id вместе с фильтрами специализации, грейда и статуса.

Опубликованы шесть демовариантов: Backend / Go / Junior и Middle, Backend / Java / Junior и Middle, Frontend / JavaScript / Junior и Middle. Java имеет 12 собственных вопросов, по шесть сложности 1 и 2, и общие вопросы SQL. В Java нет вопросов Go. Всего 56 вопросов. Есть запас для случайной сборки. Middle: порог 75%, время 30 минут.

TestAssessmentQualityEvaluation выполняет четыре варианта каждой тройки для трёх синтетических профилей знаний:

| Знания | Go Junior | Go Middle | Java Junior | Java Middle | JavaScript Junior | JavaScript Middle |
|---|---:|---:|---:|---:|---:|---:|
| Слабый: не решает задания | 0%, провал | 0%, провал | 0%, провал | 0%, провал | 0%, провал | 0%, провал |
| Средний: базовые задания и основной язык; дополнительные навыки сложности 2 не решает | 71,43%, успех | 50%, провал | 100%, успех | 60%, провал | 100%, успех | 33,33%, провал |
| Сильный: решает всё | 100%, успех | 100%, успех | 100%, успех | 100%, успех | 100%, успех | 100%, успех |

Используются реальные случайные вопросы, сохранение ответов, серверная проверка и запись категории. Четыре испытания идут на независимых кандидатах с одинаковыми знаниями: подтверждённую тройку пересдавать нельзя. Это проверка различимости синтетических типов и устойчивости баллов, не доказательство валидности экзамена для реальных специалистов. Содержание и пороги требуют оценки команды.

## Миграции и совместимость

Добавлены 20261008100001_candidate_onboarding.sql, 20261008100002_assessment_middle_bank.sql, 20261008100003_assessment_stacks.sql и 20261008100004_assessment_java_bank.sql. Номера идут после существующей 20261008100000_candidate_career.sql; применённые миграции не переименованы. Перед новым API применить миграции штатной командой migrate. Новых переменных окружения нет.

Исторические попытки и результаты не изменяются: stack_skill_id и stack_name у них null. Только известные демошаблоны получают Go или JavaScript. Старые пользовательские шаблоны не получают выдуманный стек: администратор создаёт новую версию с явным stack_skill_id. Историю удалять не нужно. Фронт необходимо обновить: старт и опрос теперь требуют stack_skill_id. Откат стековой миграции требует разрешить конфликты нескольких стековых версий для прежней пары; обычный деплой использует миграции вперёд.

PDF генерируется внутри Go. Шрифты встроены с лицензией SIL OFL; браузер, LibreOffice или PDF-сервис не нужны. Скачиваемое резюме не сохраняется в S3.
