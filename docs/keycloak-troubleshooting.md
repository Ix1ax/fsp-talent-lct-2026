# Проверка авторизации в CI

Шаг `scripts/keycloak-smoke.sh` получает токен локального тестового пользователя
и обращается с ним к `/api/v1/me`. Он проверяет реальные Keycloak, JWKS и API,
а не только доступность контейнеров.

Если в JWT нет `sub`, проверьте стандартный scope `basic`: он должен быть
подключён как **Default** к клиентам `fsp-web`, `fsp-swagger` и, только в локальном
окружении, `fsp-local-test`. В актуальных версиях Keycloak именно этот scope
добавляет идентификатор пользователя в токен. API требует непустой `sub`,
`aud=fsp-api` и подтверждённую почту, а также проверяет подпись, issuer и срок действия.
Проверки токенов отключать не нужно.

## Уже созданный realm

Импорт при запуске Keycloak не обновляет существующий realm. Поэтому после
изменения JSON-файлов обычный перезапуск контейнера не исправит уже созданных
клиентов. В панели администратора откройте realm `fsp`, затем **Clients → нужный
клиент → Client scopes → Add client scope**, выберите `basic` и добавьте его
как **Default**. После этого получите новый токен; старый токен не изменится.

Не удаляйте базу Keycloak или Docker volumes ради повторного импорта: это удалит
пользователей. В CI окружение создаётся заново, поэтому исправленные настройки
импорта применяются сразу.

Тестовый клиент с входом по паролю и тестовый пользователь присутствуют только
в `infra/keycloak/local/fsp-realm.json`. Серверный импорт не должен их содержать.

Источник: [изменения Keycloak 25 — стандартный scope basic](https://github.com/keycloak/keycloak/blob/main/docs/documentation/upgrading/topics/changes/changes-25_0_0.adoc).
