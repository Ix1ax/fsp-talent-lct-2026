# Истечение предложений о работе

Предложение без ответа действует **336 часов (14 суток) с `created_at`**.
В момент достижения дедлайна `sent` и `viewed` возвращаются как `expired`.
Просмотр кандидатом не продлевает срок. `accepted` и `rejected` остаются
ответами кандидата независимо от возраста предложения.

## API для фронтенда

- Списки и карточки работодателя, кандидата и администратора возвращают `expired`.
- Фильтр `status=expired` доступен в списках предложений всех трёх кабинетов.
  Фильтрация и `total` используют вычисляемый статус до пагинации.
- `POST /api/v1/me/offers/{offer_id}/respond` после дедлайна возвращает
  **409 `offer_expired`** с сообщением «срок предложения истёк; ответить на него нельзя».
  Проверка учитывает время после ожидания блокировок и непосредственно при записи.
- `POST /api/v1/me/offers/{offer_id}/view` возвращает истёкшее предложение с 200,
  не записывая новый просмотр и не меняя даты.
- `responded_at` у истёкшего предложения остаётся `null`. Контакты кандидата
  через такое предложение не раскрываются. Истечение не считается отказом.
- В административной статистике `offers.expired` считается отдельно;
  `accepted` и `rejected` включают только реальные ответы.

Фронтенду нужно добавить подпись «Истекло», пункт фильтра `expired`, скрыть
кнопки ответа для этого статуса и обработать `409 offer_expired`, если срок
наступил после открытия карточки. Предупреждение на седьмой день не меняется.

## Кулдаун и история

Истёкший оффер перестаёт удерживать 30-дневный кулдаун банка соискателей и
подборок потребностей. Автоматический просмотр, записанный одновременно с
отправкой этого оффера, также перестаёт удерживать срок. При отсутствии других
оснований `next_available_at=null`, кандидат снова попадает в обычную выдачу.

При этом `has_offer`, `viewed`, `last_offered_at` и `last_viewed_at` сохраняются:
это исторические признаки. Более поздний ручной просмотр и другие неистёкшие
офферы (включая принятые/отклонённые) сохраняют собственный 30-дневный срок.
Новый оффер запускает новый срок; другая компания не затрагивается.

Квоты на количество активных офферов в текущем бэкенде нет. Истечение не
добавляет новую квоту и не меняет дневной лимит публикации заданий.

## Развёртывание

Статус вычисляется при запросе: фоновые задачи, cron, миграция и новые
переменные окружения не нужны. В БД остаются исходные `sent`/`viewed`, а история
ответов не переписывается. Правило сразу применяется к старым предложениям.
Прямые SQL-отчёты должны учитывать возраст `sent`/`viewed`, а не только столбец
`status`; API уже делает это.

API расширен новым значением enum и счётчиком статистики: фронтенд с закрытым
набором статусов нужно обновить вместе с бэкендом. Откат к старой версии API
снова разрешит ответы на такие сохранённые `sent`/`viewed`.
